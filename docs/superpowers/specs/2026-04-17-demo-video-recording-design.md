# Codify Demo Video Recording — Design Spec

## Overview

录制一个 4-5 分钟的 Codify 系统演示视频，面向技术决策者/管理层，展示系统的核心价值和完整功能。使用 Playwright 自动化浏览器操作并录制视频，确保操作流畅、节奏舒适。

## 技术方案

- **工具：** Playwright (TypeScript/Python) + 内置视频录制
- **分辨率：** 1920×1080 (16:9)
- **目标环境：** `http://192.168.50.129:8880/`
- **界面语言：** 中文
- **视频格式：** WebM (Playwright 原生输出)

## 录制节奏规范

### 停顿策略
| 场景 | 停顿时长 | 目的 |
|------|----------|------|
| 页面加载完成后 | 2-3 秒 | 让观者看清页面全貌 |
| 关键操作前 | 1 秒 | 预示即将发生的动作 |
| 重要结果展示 | 2-3 秒 | 让观者吸收信息 |
| 表单填写间隔 | 0.5-1 秒 | 模拟真实操作节奏 |
| 页面切换过渡 | 1.5 秒 | 自然的导航体验 |

### 操作模拟
- **打字速度：** 每字符 60-100ms，模拟真实人类输入
- **鼠标移动：** 使用 `page.mouse.move()` 平滑移动到目标元素
- **滚动：** 使用 `page.mouse.wheel()` 或 `smoothScroll` 实现平滑滚动
- **点击：** 每次点击前短暂停顿（200ms），点击后等待页面响应

## 演示脚本（6段）

### 第一段：登录（~20秒）

**目标：** 展示系统入口和认证能力

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | 导航到 `/login` | 等待页面加载 |
| 2 | 展示登录页全貌（品牌、双认证） | 停顿 2.5 秒 |
| 3 | 确认/切换到中文界面 | 停顿 0.5 秒 |
| 4 | 输入用户名（模拟打字） | 打字动画 |
| 5 | 输入密码（模拟打字） | 打字动画 |
| 6 | 点击"登录"按钮 | - |
| 7 | 等待跳转到 Dashboard | 停顿 2 秒 |

---

### 第二段：Dashboard 总览（~45秒）

**目标：** 展示一目了然的运营全貌

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | Dashboard 页面完全加载 | 停顿 3 秒（4个指标卡：Issue状态饼图、Task状态饼图、代码变更量、Token用量） |
| 2 | 平滑滚动到活动热力图和趋势图区域 | 滚动 2 秒 + 停顿 2.5 秒 |
| 3 | 继续滚动到 MyWorkBoard 看板 | 滚动 1.5 秒 + 停顿 2 秒 |
| 4 | 平滑滚回顶部 | 滚动 1.5 秒 |

---

### 第三段：创建 Issue（~50秒）

**目标：** 展示通过 UI 发起 AI 代码生成的核心流程

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | 点击侧边栏 "Issues" | 停顿 1.5 秒展示列表页和摘要卡片 |
| 2 | 点击 "创建 Issue" 按钮 | 停顿 1.5 秒展示创建表单 |
| 3 | 选择项目（下拉选择） | 停顿 1 秒 |
| 4 | 输入标题："Demo: Echo Hello 测试" | 模拟打字 |
| 5 | 点击 Prompt Template 按钮 | 停顿 1 秒展示模板列表 |
| 6 | 选择 "Echo Hello" 模板 | 停顿 1.5 秒展示填充后的内容 |
| 7 | 选择基准分支 | 停顿 1 秒 |
| 8 | 停顿展示完整表单 | 停顿 2 秒 |
| 9 | 点击提交 | - |
| 10 | 等待跳转到 Issue 详情页 | 停顿 2 秒 |

---

### 第四段：实时等待与结果展示（~60秒）

**目标：** 展示任务执行的实时追踪能力和完整结果

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | Issue 详情页展示初始状态 | 停顿 2 秒 |
| 2 | 点击关联 Task 进入 Task 详情页 | 停顿 1.5 秒 |
| 3 | 等待状态变为 RUNNING | 轮询等待，展示状态变化 |
| 4 | 滚动到执行过程面板 | 平滑滚动 |
| 5 | 展示实时日志流 | 停留 10-15 秒（根据实际执行时间调整） |
| 6 | 等待任务完成（COMPLETED） | 停顿 3 秒展示完成状态 |
| 7 | 滚动展示结果（分支、MR链接、变更统计） | 滚动 + 停顿 2 秒 |
| 8 | 返回 Issue 详情页 | 停顿 2 秒展示分支流可视化 |

**注意：** Echo Hello 任务执行较快。如果超过 120 秒未完成，脚本会跳转到一个已完成的任务继续展示。

---

### 第五段：运维与监控（~45秒）

**目标：** 展示系统管理和数据洞察能力

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | 点击侧边栏 "Monitor" | 停顿 2 秒展示概览指标 |
| 2 | 展示 Kanban 视图（运行中/排队中任务） | 停顿 2.5 秒 |
| 3 | 点击侧边栏 "Analytics" | 停顿 2.5 秒展示趋势图表 |
| 4 | 滚动展示4个趋势图（任务量、代码变更、时长、Token） | 滚动 2 秒 + 停顿 2 秒 |
| 5 | 点击侧边栏 "Schedule Overview" | 停顿 2.5 秒展示24小时时间线 |

---

### 第六段：配置与管理（~30秒）

**目标：** 快速展示管理员能力，作为收尾

| 步骤 | 动作 | 等待/停顿 |
|------|------|-----------|
| 1 | 点击侧边栏 "Access Management" | 停顿 2 秒展示用户卡片 |
| 2 | 点击侧边栏 "Configuration" | 停顿 2 秒展示配置概览 |
| 3 | 切换到 "AI Providers" Tab | 停顿 1.5 秒 |
| 4 | 切换到 "GitLab" Tab | 停顿 1.5 秒 |
| 5 | 最终停顿 | 停顿 2 秒（结束画面） |

---

## Playwright 实现要点

### 视频录制配置
```typescript
const context = await browser.newContext({
  viewport: { width: 1920, height: 1080 },
  recordVideo: {
    dir: './videos/',
    size: { width: 1920, height: 1080 }
  },
  locale: 'zh-CN'
});
```

### 辅助函数
- `humanType(page, selector, text, delay?)` — 模拟人类打字，每字符 60-100ms
- `smoothScroll(page, deltaY, duration)` — 平滑滚动
- `pause(ms)` — 停顿等待
- `waitForNavigation(page, url)` — 等待页面跳转
- `clickWithDelay(page, selector, delay?)` — 带预停顿的点击
- `waitForTaskStatus(page, status, timeout)` — 轮询等待任务状态变化

### 容错机制
- 任务执行超时（120秒）后跳转到已完成任务
- 页面加载超时自动重试
- 元素不可见时等待或跳过

### 登录凭据
- 凭据从环境变量读取（`DEMO_USERNAME`, `DEMO_PASSWORD`）
- 不硬编码在脚本中

## 文件结构

```
scripts/
  demo/
    record-demo.ts       — Playwright 录制脚本（主入口）
    helpers.ts           — 辅助函数（humanType, smoothScroll, pause 等）
    package.json         — 依赖声明（playwright）
videos/
  codify-demo.webm       — 录制输出
```

## 输出物

- `videos/codify-demo.webm` — 录制的原始视频
- `scripts/demo/` — 可重复执行的录制脚本
