Design Section 1: Component Architecture

How the filter/sort system is organized

Component Tree

📦 FilterToolbar.vue — Generic container component
├── 🔍 SearchBox — inline text input (debounced)
├── ⊕ FilterButton → FilterPopover.vue
├── Category list (Status, Project, Priority...)
└── Submenu with options (checkboxes + counts)
├── ↕ SortButton → SortPopover.vue
├── Field select dropdown
└── Direction toggle (asc/desc)
├── ⚙ ColumnsButton → ColumnsPopover.vue
└── Toggle switches per column
└── 🏷 ActiveFilterChips — removable tag row

Key Design Decisions

COMPOSABLE
useFilterSort(config)
Holds all state, localStorage persistence, computed API params. Pages pass config describing their fields.
FILTER CONFIG
Declarative field definitions
Each filter field = { key, label, type, options, apiParam }. Pages define their own field arrays.
POPOVER PATTERN
NPopover + custom content
Use NPopover (not NDropdown) for full control over submenu rendering. No cascading — use single panel with back navigation.
PERSISTENCE
localStorage per page
Key: `codify:filters:issues` / `codify:filters:tasks`. Saves filters + sort + column visibility.
