Design Section 4: Backend API Changes

New query parameters for server-side filtering & sorting

GET /api/issues

Param Type Status
status string (multi, comma-sep) Enhance — currently single
project_id int Exists
search string New — ILIKE on title
created_after datetime ISO New
created_before datetime ISO New
sort_by enum: created_at, status New
sort_order enum: asc, desc New

GET /api/tasks

Param Type Status
status string (multi, comma-sep) Exists
project_id int Exists
issue_id int Exists
initiator_username string Exists
priority string (multi, comma-sep) New
search string New — ILIKE on user_prompt
created_after datetime ISO New
created_before datetime ISO New
sort_by enum: created_at, status, priority New
sort_order enum: asc, desc New

Implementation Notes

SEARCH
Uses ILIKE '%{term}%' on title/user_prompt. No full-text search index needed at this scale.
MULTI-STATUS (ISSUES)
Enhance issues endpoint to accept comma-separated status values like tasks already does.
SORTING
Default: sort_by=created_at&sort_order=desc. Validate against allowed enum values.
NO MIGRATION
All new params are query filters on existing columns. No DB schema changes needed.
